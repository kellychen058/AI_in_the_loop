Section 1 — What AI tools we plan to use, and what we will use each for
We will use Claude for planning, including clarifying requirements, breaking down tasks, and comparing design options. The team will make the final decisions.
We will use Matt Pocock’s skills to support this workflow: /grill-me to challenge assumptions, /to-spec to document agreed requirements and decisions, and /to-tickets to break the plan into tasks.
We will use Codex to implement the approved plan and write tests. Team members will review and test generated code before merging and write PR descriptions and decision records themselves.
API keys, credentials, and permission-related code and settings will be handled exclusively by team members, without AI access or modification.
We will use GitHub Copilot's inline autocomplete while typing — not as a substitute for writing the PR description or DECISIONS.md entry ourselves.
Section 2 — How we will document AI interactions
Our prompt engineering log will record prompts and models used for AI contributions included in the repo, noting what we kept or changed and why.
We will maintain an implementation log in each task ticket generated by  /to-tickets , linking relevant prompt entries and PRs and recording test results. Team members will verify it before merging.
One-off debugging questions or syntax lookups do not need separate entries unless their output contributes to code, text, or decisions included in the repo.
Section 3 — How we will handle disagreements about AI output quality
"If two engineers disagree about whether AI-generated code is good enough to merge, the code steward has final say — not whoever wrote the prompt, and not whoever has more experience."
"Evidence required before a merge decision: passes the existing test suite, passes the PR review checklist, and can be explained by someone other than whoever generated it."
